# CoSyDelay v9: clean from-scratch formal protocol

This package removes the archived-expression incumbent used by v4/v6/v8.
It performs one P10/G10 evolution. Every initial expression is generated by
the LLM during the current run, and every survivor decision uses the same full
Training fitness reproduces the paper implementation:

`min(max(mean_over_approaches(max(0, R2)) + physical_consistency, 0), 2)`.

Physical consistency is binary. Because v9 rejects physically invalid fitted
candidates before population admission, every survivor receives a consistency
value of 1 and is consequently ranked by the paper's nonnegative approach-macro
Training R2. RMSE and MAE are reported but do not alter evolutionary selection.

The result records both selection and reporting metrics. Formal comparison to
the data-driven models uses raw approach-macro R2 and pooled RMSE/MAE, exactly
matching their evaluation script; the paper's per-approach nonnegative R2 is
used only for symbolic-evolution fitness.

Each expression uses L-BFGS-B with exactly 10 starts. Approach blocks run with
at most four workers. Offspring may replace one of those ten starts with the
immediate current parent's fitted coefficients; this is a symmetric internal
evolution operator, not an external warm start and not extra optimizer budget.

The pre-fit gate enforces grammar, feature use, time dimensionality, numerical
domain checks, obvious derivative directions, exact zero delay at zero flow,
and a coefficient-robust symbolic R9 proof. The R9 proof is safe to run before
fitting because all fitted coefficients have strictly positive bounds; a
structure that fails this same proof would be rejected by the enhanced audit
after fitting anyway. After fitting, the enhanced hard gate requires all standard physical
rules, symbolic R8/R9 proofs, and dense checks of finiteness, non-negativity,
nondecreasing flow response, and nonincreasing green response. No fixed R9 term
is appended.

The v9 prompt uses a coefficient-robust construction contract: the complete
expression retains global `Cycle_Time * flow_lane / GR_phase` factors and a
positive finite modifier. It prohibits coefficient-difference signs, fitted
green exponents as the sole R9 mechanism, subtractive cancellation, and
green-only or constant branches. Failed checks are returned as short structural
R2/R3/R7/R8/R9 repair instructions; full verifier details remain in audits.
It also explicitly limits identifiers to `a1`--`a8` and returns a precise
coefficient-budget correction after an `a9+` output. Real-API P3/G2 pilots on
I1/I2 produced 18/18 valid outputs and 18/18 enhanced-physics passes; these are
prompt-yield checks, not formal P10/G10 accuracy results.

Within one generation batch, malformed, illegal, or duplicate LLM outputs are
regenerated at most five times. A population slot may start at most 30 batches
when a syntactically valid candidate later fails fitting or fitted physics. An
individual API transport/output request has at most five provider attempts.
Canonical duplicates are rejected across the entire current evolution.

The formal LLM request is locked to `gpt-4.1-mini` and preserves the original
CoSyDelay provider-default behavior: `temperature`, `top_p`, and `max_tokens`
are not sent in the request body. Seed 20260712 remains explicitly requested.
The runner aborts if environment overrides differ. It records the provider
endpoint, call times, request alias, actual response-model strings, which
sampling fields were explicitly sent, retry metadata, and token usage.
Acceptance of a seed field does not by itself prove provider-side determinism;
that limitation remains explicit in the result.

The formal runner has no incumbent, Validation, Test, population, generation,
or seed arguments. The evolution seed is fixed as `20260830 + 10000 *
intersection_id`. Its project-artifact read allow-list blocks Validation/Test,
renamed datasets, cached models, and historical result files. It refuses output
reuse and fails unless all 10 initial survivors and all 10 generations
complete. The winning coefficients are the ones already fitted during
evolution; there is no post-search CV reranking or refit. The formal optimizer
adapter exposes no CV/incumbent/polish interface and freezes maxiter/maxfun at
200/20000.

Coefficient bounds use the pre-v6 baseline profile (`scale [0.001,1000]`,
`power exponent [0.05,5]`, `exp coefficient [0.0001,1]`). A counterbalanced
I1--I6 Training-only fixed-structure benchmark found no meaningful accuracy,
physics, or efficiency benefit from the later expanded profile, so the
Test-informed expanded-bounds choice is not part of this clean method.

```powershell
$env:LLM_API_KEY = '<rotated provider key>'
python Parameters_sensitive/gmini/methods/cosydelay_v9_clean_from_scratch/run_formal_training_search.py `
  --intersection 1 `
  --output Parameters_sensitive/gmini/methods/cosydelay_v9_clean_from_scratch/experiments/formal_i1/run_01
```

The repository's existing Test has already been viewed during earlier method
development. Consequently, even this clean code path cannot make that old Test
project-wide unseen again. A once-only evaluation on newly generated or truly
external frozen scenarios is still required for an unbiased final paper claim.
